# Conductor — архитектура

Как устроен бот и куда класть новое. Прикладывается к каждому запросу на доработку: правила ниже проверяются тестами, а не памятью.

Что бот делает для людей — [FEATURES.md](FEATURES.md). Как это выглядит — [UI-KIT.md](UI-KIT.md). Предрелизная приёмка — [ACCEPTANCE.md](ACCEPTANCE.md). Памятка открытого теста — [OPEN-TEST.md](OPEN-TEST.md).

## 1. Слои и правило зависимостей

```
             ┌─────────────────────────────────────────┐
   Discord ──▶            cogs/                        │  события и команды
             │  тонкие: разобрать вход, позвать        │
             │  сервис, отрисовать ответ               │
             └───────┬──────────────────────┬──────────┘
                     │                      │
             ┌───────▼─────────┐   ┌────────▼──────────┐
             │   services/     │   │  presentation/    │
             │ оркестрация,    │   │  как это выглядит │
             │ БД, Discord API │   │  (V2, движение)   │
             └───────┬─────────┘   └────────┬──────────┘
                     │                      │
             ┌───────▼──────────────────────▼──────────┐
             │                domain/                  │
             │  чистые правила: ранги, пороги, счёт,   │
             │  иерархия, классификация. Без Discord,  │
             │  без БД, без «сейчас» по умолчанию      │
             └─────────────────────────────────────────┘
                                  │
                          ┌───────▼────────┐
                          │      db/       │
                          │ модели, сессии │
                          └────────────────┘
```

**Правило зависимостей — единственное, что нельзя нарушать:**

| Слой | Импортирует | Никогда не импортирует |
| --- | --- | --- |
| `domain/` | стандартную библиотеку | `discord`, `sqlalchemy`, `services`, `cogs` |
| `db/` | `sqlalchemy` | `discord`, `services`, `cogs` |
| `presentation/` | `discord`, `domain` | `sqlalchemy`, `services`, `cogs` |
| `services/` | всё, кроме `cogs` | `cogs` |
| `cogs/` | всё | — |

Проверяется машиной: `tests/test_layering.py` разбирает импорты через `ast` и падает при нарушении. Тест же запрещает новый пакет-слой мимо правила и вызовы на верхнем уровне модулей домена.

Отсюда следствие: **значимый объект, который читают два слоя, живёт в `domain/`.** Карточка события должна знать форму данных, но не должна зависеть от того, кто их собрал (`domain/records.py`).

Почему так: почти тысяча тестов работает без Discord и без сети ровно потому, что правила живут в `domain/`. Как только порог репутации переедет в cog, проверить его можно будет только поднятием бота.

## 3. Инварианты системы

Девять правил, каждое закрывает конкретный класс аварий. Нарушение любого — повод остановить реализацию, а не «поправить потом».

### И1. Роли меняются только через брокер

`add_roles` и `remove_roles` вызываются **исключительно** в `services/role_broker.py`. Роли одного человека хотят менять восемь подсистем — ранги, Old, лестница, репутация, достижения, подписки, верификация, мут. Без единой точки они перетирают друг друга. Проверяется тестом по исходникам: любой вызов вне брокера — падение сборки.

### И2. Отправка в канал только через очередь

Обработчик события никогда не ждёт сетевой отправки, всё уходит в `log_pump`. Ответы на взаимодействия — исключение: у них окно в 3 секунды.

### И3. Одна периодическая задача — один планировщик

Никаких самодельных `while True: await asyncio.sleep(...)`. Регистрация в `services/scheduler.py`, джиттер обязателен, иначе все задачи бьют в одну секунду минуты.

### И4. Долгое ожидание — не `sleep`, а отложенное действие

«Удалить комнату через 40 секунд, если никто не вернулся» — это `schedule_later(key, delay)` с `cancel_later(key)`. Спящая корутина не переживает рестарт и не отменяется.

### И5. Ни одного вызова Discord внутри открытой транзакции

Транзакция читает и пишет, затем закрывается, затем идёт работа с сетью, затем короткая транзакция фиксирует результат. Обратный порядок держит блокировку записи SQLite минутами — это уже случалось с массовой выдачей Old.

### И6. Состояние в БД, память — только кэш

Всё, что должно пережить рестарт (владелец комнаты, таймер розыгрыша, открытый тикет, сообщение панели), лежит в таблице. Словарь в памяти допустим только как кэш с восстановлением.

### И7. Приведение к желаемому состоянию идемпотентно

Сверка запускается повторно и не делает лишних вызовов API. Формула: «прочитать желаемое → прочитать фактическое → применить разницу», а не «сделать действие».

### И8. Кэш без инвалидации — дефект

Каждый кэш объявляет событие, которое его сбрасывает: ранг — на смену ролей, конфиг — на правку, владелец комнаты — на передачу, живые каналы тикетов — на любое изменение состояния тикета.

### И9. Ошибка не уходит наружу сырой

Пользователь видит карточку с кодом `E-xxxx`. Разработчик видит `structlog` с `guild_id`, `user_id`, действием, кодом и трассировкой. Содержимое сообщений участников в уровень INFO не попадает никогда.

### Контракты взаимодействий

Правила ниже введены планом открытого теста и проверяются машиной: новая кнопка, модалка или отправка не обходят их.

**К1. Вложения.** `ui.File` создаётся только в `presentation/layout.py`. Карточка с файлом уходит в Discord только через помощники layout (`respond`, `send_card`, `edit_card`, `update_message`, `edit_response`), которые прикладывают `files=` или `attachments=`. Держит `tests/test_send_contract.py`.

**К2. Отправка карточек.** Вызовы `.send` / `.edit` / `.send_message` / `.edit_message` / `.edit_original_response` с `view=` живут только в `presentation/layout.py` и `presentation/motion.py`. Остальной код зовёт помощники. Держит `tests/test_send_contract.py`.

**К3. Модалки.** Каждая наследует `SafeModal`; обработчик — `submit()`, не `on_submit()`; ответ Discord (defer) уходит до обращения к сервису. Ошибка формы попадает в `CriticalLog` с кодом `E-XXXX`. Держит `tests/test_modal_contract.py`.

**К4. Кнопки и селекты.** Фичи — `PersistentButton` / `PersistentSelect`; `callback` не переопределяется; работа — в `on_action()`; ошибки идут в `CriticalLog`. Держит `tests/test_component_contract.py`.

**К5. Ответ до разрушения.** Если действие удаляет или прячет канал или сообщение, где нажата кнопка, пользователь получает ответ до удаления (`split_teardown` / `run_teardown`). Держит `tests/test_evidence_close.py` и сценарии архива групп.

**К6. Упоминания.** Не больше 100 id в одном сообщении; массовый пинг — пачками через `services/broadcast.py`; непустые `AllowedMentions` — только `presentation/mentions.py`. Держит `tests/test_mentions.py` и `tests/test_broadcast.py`.

**К7. Длинные списки.** Карточка показывает первые строки и «и ещё N»; полный список — через постраничный Roster, а не одним текстом. Держит `tests/test_roster.py`.

**К8. Лимиты Discord.** Числа платформы берутся только из `domain/discord_limits.py`. Держит `tests/test_discord_limits.py`.

**К9. Предупреждения — ошибки теста.** `DeprecationWarning` и `PendingDeprecationWarning` из модулей `conductor` валят pytest. Держит `tests/test_warnings_policy.py`.

## 4. Потоки

### Слэш-команда

```
Discord ──▶ cog: команда
             1. guild_only, разбор аргументов
             2. can(member, key)                 ─▶ domain/access
             3. ack(interaction), если работа > 1 с
             4. сервис делает работу             ─▶ services/*  ─▶ db
             5. смена ролей — только брокер      ─▶ services/role_broker
             6. layout.panel(...)                ─▶ presentation
             7. followup / edit_original_response
```

Сначала «имеет ли право», потом работа. Кто обслуживается — `bot.serves` и `domain/guilds.py`.

### Нажатие кнопки

```
Discord ──▶ DynamicItem.from_custom_id ──▶ guard (UI-KIT §8) ──▶ сервис ──▶ edit_message
```

Страж — общий декоратор, а не копия проверок в каждом обработчике. Кнопка, которая открывает модалку, не деферит взаимодействие: `acks_first = False`, а `ack()` вызывает уже `on_submit`.

### Событие шлюза

```
Discord ──▶ cog: слушатель
             1. фильтр (бот? лог-канал? нужная гильдия?)
             2. телеметрия в буфер            ─▶ services/activity (в память)
             3. карточка в очередь            ─▶ log_pump (не ждём)
             возврат управления немедленно
```

Слушатель не ходит в БД синхронно и не ждёт сеть. Если проверка «а это вообще наш канал» неизбежна, она идёт через кэш с TTL, а не через SELECT на каждое сообщение.

### Фоновая сверка

```
scheduler (период + джиттер)
   ──▶ прочитать желаемое состояние из БД
   ──▶ прочитать фактическое из кэша Discord
   ──▶ разница ──▶ очередь ──▶ role_broker / voice_rooms
```

## 5. Рецепт новой фичи

1. **Правило — в `domain/`.** Чистая функция плюс тест. Ни Discord, ни БД. Время передаётся аргументом `now`, чтобы тест не зависел от часов.
2. **Схема — в `db/models.py` плюс миграция.** Гильдейская таблица несёт `guild_id`; ресурс с владельцем — `owner_id`, `created_at`, `closed_at`, `closed_by`. Частичный уникальный индекс объявляется сразу для обоих движков (`sqlite_where` **и** `postgresql_where`).
3. **Ключ прав — в реестр** `domain/access.py` и в `data/permissions.yml.example` одной правкой: тест сверяет их состав и порядок. Ключа нет в реестре — ключа не существует.
4. **Оркестрация — в `services/`.** Здесь БД и Discord API, вызовы брокера, планировщика, очередей.
5. **Внешний вид — в `presentation/`.** Карточка собирается `layout.panel(...)`, длинная операция — контроллером из `motion.py`. Ни одной строки текста в cog и в `domain/`.
6. **Вход — в `cogs/`.** Разобрать, позвать, отрисовать.
7. **Тесты.** Домен без Discord. Права: отказ и иерархия обязательны. Идемпотентность, если есть сверка. Время — на поддельных часах.
8. **Восстановление.** Что произойдёт при рестарте посреди операции? Если ответ «потеряется» — состояние лежит не в том месте.

### Чек-лист приёмки

- [ ] Правило вынесено в `domain/` и покрыто тестом без Discord
- [ ] Миграция применяется на существующую базу без потери данных
- [ ] Ключи прав есть и в реестре, и в примере YAML
- [ ] Ни одного вызова Discord внутри транзакции
- [ ] Ни одного прямого `add_roles` вне брокера
- [ ] Взаимодействие подтверждается до долгой работы, отказ рисуется карточкой
- [ ] Панель и таймеры переживают рестарт
- [ ] Кэш имеет событие инвалидации
- [ ] Длинная операция показывает прогресс и укладывается в бюджет правок
- [ ] `ruff check` и `pytest` зелёные

| --- | --- | --- |
| Таблица | множественное число, змеиный регистр | `voice_rooms`, `mod_cases` |

## 7. Данные и время

- Snowflake — **только** `BigInteger`. `Integer` переполнится.
- Время — `DateTime(timezone=True)`, всегда UTC. Конвертация только на выводе, через `discord.utils.format_dt` или часовой пояс гильдии (`guild_config.tz_for`).
- Сутки, границы недели и время дайджеста считаются в поясе сервера, а не в UTC.
- Функции домена принимают `now: datetime | None = None`: значение по умолчанию берётся внутри, тест передаёт своё.
- Метод с параметром `now` пробрасывает его в каждый вызываемый метод, у которого тоже есть `now`. `datetime.now(UTC)` — только умолчание в том методе, которому `now` не передали.
- Дедупликация уведомлений о каркасе — по отпечатку состояния (`structure_fingerprint` в `domain/observe.py`), не по часу в памяти процесса. Совпадение отпечатка — молчать после рестарта. Потолок — `STRUCTURE_CARD_CAP` карточек за прогон, остальное сводкой. Сам отпечаток хранится в БД колонки гильдии, не в `dict` процесса; колонку заводит секция, которая пишет уведомления.
- Денормализация допустима там, где она уже есть (`MemberRecord.message_count` рядом с `MemberDaily`), но пересчёт должен быть возможен из первичных таблиц.
- Мягкое удаление там, где есть история: `closed_at` вместо `DELETE`.
- Миграция Alembic: перед файлом — `alembic heads`, одна голова; `down_revision` — строго на неё; `revision` вида `"0068"`. Тело — через `inspect(op.get_bind())`: проверить таблицу и колонку, затем менять. Переименование колонки — добавить, перелить `op.execute(sa.text(...))`, охранённо удалить; не `alter_column(new_column_name=...)` (SQLite и Postgres ведут себя иначе). `downgrade` симметричен и так же охранён.

## 8. Отказы и восстановление

| Отказ | Поведение |
| --- | --- |
| Discord недоступен | discord.py переподключается сам; тяжёлый бутстрап в `on_ready` защищён флагом |
| Нет права у бота | Действие не выполняется, причина попадает в `/diagnose`, при повторе — карточка в лог администрации |
| Роль бота ниже целевой | Брокер отклоняет заявку с внятной причиной, не пытается и не молчит |
| Привязанная роль удалена | Брокер пропускает её id и ставит остальные; одна карточка на гильдию, пока роль не привяжут заново |
| Очередь логов переполнена | Считается `dropped`, жалоба не чаще раза в минуту, счётчик виден в `/diagnose` |
| Rate limit на переименовании | Ожидание не дольше 30 с (`max_ratelimit_timeout`), дальше — отложенный повтор |
| Взаимодействие устарело | Коды 10062, 40060, 50027 глотаются молча: это закрытая пользователем панель |
| Рестарт посреди операции | Состояние в БД, сверка при старте приводит мир к желаемому |
| База недоступна | Бот не пишет телеметрию, но продолжает отвечать; авария уходит в лог администрации |
| Процесс завис | `.heartbeat` перестаёт обновляться, healthcheck контейнера видит это через 120 с |
| Канал каркаса удалён | Привязки обнуляются, панели гасятся, карточка в `#структура` с кнопкой восстановления |
| Discord подтвердил 429 на создание | Сид и создание каналов получают источник `discord`, запись в файл не дольше часа, повтор после окна безопасен |
| Предсказание discord.py или общий лимит | Источники `library` и `shared`: честный текст, только память процесса, файл не пишется |
| Квота бота на создания | Источник `local`: бот сам притормозил, файл не пишется |
| Предохранитель `invalid_stop` | Полосы USER/STAFF/BACKGROUND остановлены; ответы на взаимодействия идут |
| Defer регулятора | Честная карточка ожидания, создание продолжается через очередь, а не отказ |

## 9. Тестирование

| Уровень | Что | Чем | Доля |
| --- | --- | --- | --- |
| Домен | пороги, ранги, иерархия, счёт | обычный `pytest`, без моков | больше половины |
| Представление | сборка карточек, лимиты V2 | снапшоты, без сети | заметная |
| Сервисы | БД, идемпотентность, сверка | SQLite во временном файле | заметная |
| Cog | разбор входа, маршрутизация | моки на границе Discord | немного |
| Живой Discord | — | ручная проверка на тестовом сервере | — |

Схема для тестов строится один раз за сессию и дальше реплеится из слепка; маркер `real_migrations` прогоняет всю цепочку Alembic по-настоящему. Обязательный минимум для фичи с правами — тест на отказ без ключа и тест на иерархию; для сверки — тест на идемпотентность; для таймера — тест на поддельных часах. Время в тестах не берётся из системных часов, задержки не проверяются реальным `sleep`.

## 10. Что запрещено

| Запрет | Почему |
| --- | --- |
| `discord` в `domain/` | Ломает тестируемость правил |
| SQL и `session_scope` в `cogs/` | Логика утекает из сервисов, транзакции живут дольше нужного |
| Прямой `add_roles` вне брокера | Гонки между подсистемами (И1) |
| `asyncio.sleep` для отложенного действия | Не переживает рестарт, не отменяется (И4) |
| `print` вместо `structlog` | Теряется контекст гильдии |
| Голый `except:` и `except Exception: pass` | Ошибка исчезает бесследно |
| Новый `except Exception` без `structlog` / типизированной причины | Тот же класс дефекта: отказ немой |
| Немой `return None` в новом коде отказа | Нужна типизированная причина (`RoomDenial`, `EvidenceDenial`, `ReadyIssue`), не тишина |
| Текст для человека в `cogs/` или `domain/` | Невозможно вычитать тон и перевести |
| Сырой `0x…` цвет | Обходит систему токенов |
| Discord Administrator как универсальный ключ | Запрещено моделью прав после привязки Специального; до привязки — временный вход свежего сервера и обход лимитов |
| Новый `discord.Embed` | Весь интерфейс — Components V2 |
| Правка сообщения чаще бюджета из UI-KIT §5 | Мигание у читателя и лимиты у Discord |

## 11. Точки расширения

- **Новая роль под управлением** → объявить владеющую подсистему в брокере. Больше ничего.
- **Новый вид панели** → `kind` в `custom_id`, класс `DynamicItem`, строка в `PANEL_KINDS`.
- **Новый сервис** → атрибут в `Conductor.__init__` после своих зависимостей; периодические задачи — внутри `__init__` сервиса через `scheduler.every` (не в `bot.py`, там только `panels-probe` и `heartbeat`); `DynamicItem` — `register_dynamic_item`; новый cog — строка в `COGS`.
- **Новое право** → строка в `domain/access.py` и в `data/permissions.yml.example`, затем `can(...)` в обработчике.
- **Новая периодическая работа** → регистрация в планировщике.
- **Новый вид санкции** → тип дела в `mod_cases` плюс правило падения репутации.
- **Новая метрика диагностики** → счётчик в сервисе плюс строка в `/diagnose`.
- **Цифра «как сервер сейчас»** → только `services/pulse.py`; канал статистики, вкладка «Сейчас» и сигналы читают этот снимок, а не пишут свой SQL.
- **Новый сигнал пульса** → вид в `domain/observe.py`, порог в `domain/pulse.py`, эмит в `ObserveService`, текст в `presentation/copy/`.
- **Новая страница `/admin`** → `AdminPage` в `domain/admin.py`, модуль `services/admin_<id>.py`, `register` в `admin_pages.py`.
- **Новая строка каркаса** → запись в `SKELETON` с `feature`, привязка в `_persist`, при необходимости ячейка в `RIGHTS`. Больше ничего.
- **Новое правило автомода** → ключ в `data/automod.yml.example` и разбор в `domain/automod.py`. В `/admin` правило не заводится.
- **Новый тег подписки** → константа в `domain/self_roles.py` плюс строка на странице «Роли по выбору».
- **Новый язык интерфейса** → второй каталог в `presentation/copy/`. Поэтому строки и не живут в cog.

## 12. Как это выглядит на 600 участниках

Цифры — профиль **edge**, он же умолчание `RATE_PROFILE`. `balanced` и `safe` ниже; `safe` — аварийный откат одной строкой в `.env`.

| Показатель | Ориентир |
| --- | --- |
| Сообщений в буфере до сброса | сброс раз в 30 с, пачкой |
| Записей в очереди логов | до 2000, свыше — потеря; рабочий на канал, склейка от 3 карточек, глобальный темп у регулятора |
| Одновременных REST | 24 (семафор профиля); полоса INTERACTION вне этого числа |
| Склейка ролей на человека | окно 3 с, побеждает последнее желаемое состояние; гистерезис в домене, не блокировка по времени |
| Нажатия кнопок | 12 за 10 с на участника; потолок гильдии `INTERACTION_LIMIT_PER_MINUTE` (в профиле 1200/мин; `50` в `.env` = взять из профиля) |
| Правок одного сообщения | не чаще 1 раза в 2 с (бюджет UI-KIT §5) |
| Полная сверка ролей | раз в 10 минут, порциями, полоса BACKGROUND |
| Глобальный REST | 48 запрос/с; взаимодействия в потолок Discord не входят |
| Чтение ранга | из кэша, TTL 30–60 с |

Если доработка нарушает любой из ориентиров, это обсуждается до написания кода, а не после.
