# Conductor — визуальный язык

Один документ на все сообщения бота. Прикладывается к любому запросу, где есть интерфейс.
Правило: **не выдумывать оформление в cog'е**. Всё, что рисуется, собирается хелперами из `presentation/layout.py` и `presentation/motion.py`.

Проверено на **discord.py 2.7.1**: все перечисленные API, сигнатуры и ограничения подтверждены запуском, а не взяты по памяти.

Спутник: [ARCHITECTURE.md](ARCHITECTURE.md) — куда класть код. Что именно рисуется в каждом канале — [FEATURES.md](FEATURES.md) §9.

---

## 1. Принципы

1. **Одна карточка — одна мысль.** Если в сообщении две несвязанные темы, это два сообщения или два `Container`.
2. **Цвет — это смысл, а не украшение.** Акцентная полоса кодирует исход. Один оттенок не может значить «войс» в одном месте и «ошибка» в другом.
3. **Сначала ответ, потом детали.** Первая строка отвечает на вопрос. Обоснование ниже, мелким `-#`.
4. **Кнопка называет действие, а не согласие.** «Закрыть тикет», «Забрать комнату». Никаких «ОК», «Да», «Готово».
5. **Разрушительное — всегда в два шага.** Первое нажатие меняет карточку на подтверждение, второе выполняет.
6. **Движение показывает работу, а не развлекает.** Живая карточка допустима там, где человек ждёт. Там, где не ждёт, — запрещена (см. §5).
7. **Пустое состояние — это тоже дизайн.** «Ничего не найдено» с подсказкой, что делать дальше.
8. **Ноль технического мусора наружу.** Ни трассировки, ни `0x5865F2`, ни `guild_id=`, ни английских служебных имён.
9. **Мобильный первым.** Половина сервера читает с телефона: ширина около 40 символов. Пары «ключ — значение» в строку, не таблицы.

## 2. Стек Components V2

```python
import discord
from discord import ui

class Card(ui.LayoutView):
    def __init__(self) -> None:
        super().__init__(timeout=None)          # None — только для панелей, живущих в канале
        self.add_item(
            ui.Container(
                ui.TextDisplay("## Заголовок\nТело карточки."),
                ui.Separator(),
                ui.ActionRow(CloseButton()),     # ряд кнопок — ребёнок контейнера
                accent_colour=0x5865F2,
            )
        )

await interaction.response.send_message(
    view=Card(),
    ephemeral=True,
    allowed_mentions=discord.AllowedMentions.none(),   # TextDisplay пингует!
)
```

### Словарь компонентов

| Компонент | Конструктор (2.7.1) | Для чего |
| --- | --- | --- |
| `ui.LayoutView` | `LayoutView(timeout=180.0)` | Корень. `timeout=None` для постоянных панелей |
| `ui.Container` | `Container(*children, accent_colour=None, spoiler=False, id=None)` | Карточка с цветной полосой слева |
| `ui.TextDisplay` | `TextDisplay(content, *, id=None)` | Markdown-текст |
| `ui.Section` | `Section(*children, accessory=…, id=None)` | Текст плюс **обязательный** аксессуар справа |
| `ui.Thumbnail` | `Thumbnail(media, *, description=None, spoiler=False)` | Аватар или картинка как аксессуар `Section` |
| `ui.Separator` | `Separator(*, visible=True, spacing=SeparatorSpacing.small)` | Черта или воздух. Значения: `small`, `large` |
| `ui.ActionRow` | `ActionRow(*children, id=None)` | До 5 кнопок **или** 1 селект |
| `ui.File` | `File(media, *, spoiler=False)` | Вложение внутри карточки |
| `ui.MediaGallery` | `MediaGallery(*items)` | До 10 `discord.MediaGalleryItem` |
| `ui.Label` | `Label(text=…, component=…, description=None)` | Обёртка поля **в модалке** (появилась в 2.7) |
| `ui.Modal` | `Modal(title=…, timeout=None, custom_id=…)` | Ввод текста. **Не V2**, живёт по старым правилам |

`Section.accessory` — обязательный именованный аргумент: `Thumbnail` или одна `Button`. Секция без аксессуара не соберётся.

`ui.Button` принимает `emoji` типа `str | Emoji | PartialEmoji` — это точка входа для анимированных значков из §5.

### Жёсткие лимиты Discord

| Что | Предел | Что делать при превышении |
| --- | --- | --- |
| Компонентов в сообщении, со вложенными | **40** | Разбить на страницы, а не ужимать |
| Компонентов верхнего уровня | **10** | Всё складывать в один `Container` |
| Сумма текста всех `TextDisplay` | **4000** | `paginate()`, счётчик «1/3» |
| Кнопок в `ActionRow` | 5 | Новый ряд |
| Селектов в `ActionRow` | 1 | Новый ряд |
| Опций в селекте | 25 | Поиск строкой или страницы |
| Картинок в `MediaGallery` | 10 | Вторая галерея или страницы |
| Подпись кнопки | 80 | Обрезать многоточием |
| `custom_id` | 100 | Схема из §7 заведомо короче |
| Полей в модалке | 5 | Две модалки подряд, не одна перегруженная |
| Заголовок модалки | 45 | — |

### Что ломается молча

- **Нельзя** слать `content` или `embed` вместе с `LayoutView`. Discord отклонит запрос; хелперы обязаны отсекать это типами, а не рантайм-проверкой.
- Флаг `IS_COMPONENTS_V2` у сообщения **необратим**. Сообщение с эмбедом нельзя отредактировать в V2-карточку, и наоборот. Панель, которая когда-нибудь станет V2, сразу создаётся в V2. Это же ограничение делает невозможной «постепенную» миграцию одного сообщения — только целиком.
- `File` и `MediaGallery` — единственный способ показать вложение в V2. Просто передать `file=` в `send()` мало: файл прилетит, но в карточке его не будет.
- `TextDisplay` **упоминает по-настоящему**. `AllowedMentions.none()` на каждой отправке, кроме мест, где пинг задуман.
- Discord Poll API в V2-сообщении отключён. Опросы — только кнопки и селекты.
- `Message.edit` принимает `view`, но **не** принимает `content` вместе с V2-разметкой. Обновление живой карточки — это всегда пересборка `LayoutView` целиком.

## 3. Токены

Объявлены один раз в `presentation/tokens.py`. Сырых `0x…` в cog'ах не бывает.

### Акцент контейнера

| Токен | HEX | Когда |
| --- | --- | --- |
| `Tone.INFO` | `0x5865F2` | Нейтральный ответ, справка, статус, панель без исхода |
| `Tone.OK` | `0x57F287` | Действие выполнено, вход, открытие |
| `Tone.WARN` | `0xFEE75C` | Нужно решение, подтверждение, ожидание, тикет открыт |
| `Tone.DANGER` | `0xED4245` | Санкция, удаление, выход, отказ по правилам, авария |
| `Tone.MUTED` | `0x99AAB5` | Нет прав, устарело, отключено, тихое служебное |
| `Tone.SPECIAL` | `0xEB459F` | Событийное: розыгрыш, репутация, лестница, праздник |
| `Tone.RUNNING` | `0x4E5D94` | **Только** для карточки в работе (§5). Приглушённый синий: видно, что это не финал |

Семь, и седьмой существует ровно ради состояния «идёт». Больше не заводить: домен читается по заголовку и иконке, а не по восьмому оттенку.

Соответствие доменов:

| Домен | Токен |
| --- | --- |
| Следящие, модерация, бан | `DANGER` для санкции, `INFO` для справки о составе |
| Войс | `OK` при создании, `INFO` у панели владельца |
| Тикеты | `WARN` открыт, `OK` закрыт решённым, `MUTED` закрыт без ответа |
| Репутация, розыгрыш, лестница | `SPECIAL` |
| Отказ в правах | `MUTED` — отказ не авария, красным не пугать |
| Ошибка бота | `DANGER` |
| Любая операция в процессе | `RUNNING` |

### Иконки

Ровно один значок в начале заголовка. Второго в строке не бывает.

| Значок | Значение |
| --- | --- |
| `▸` | Панель, интерактив, «здесь можно нажать» |
| `✓` | Сделано |
| `⚠` | Нужно решение человека |
| `✕` | Отказано, отменено, удалено |
| `⏳` | Идёт, ждёт таймера (статический запасной вариант для §5) |
| `🔒` | Заперто, приватно, замок комнаты |
| `⚑` | Санкция, дело, жалоба |
| `★` | Награда, ступень, репутация |
| `◷` | Смена, дежурство, расписание |

Разноцветные эмодзи (🎉 🔥 💥) — только в карточке розыгрыша и праздничного сбора, максимум один на сообщение.

### Типографика внутри `TextDisplay`

| Разметка | Роль | Пример |
| --- | --- | --- |
| `## …` | Заголовок карточки | `## ✓ Тикет закрыт` |
| `### …` | Подзаголовок секции длинной карточки | `### Участники` |
| `**Ключ:** значение` | Пара «поле — значение» | `**Причина:** спам в общем` |
| `-# …` | Подпись мелким серым — замена футера эмбеда | `-# дело #128 · следящий Ann` |
| `> …` | Цитата пользовательского текста | `> ну и где мод` |
| `- …` | Список | |
| Моноширинный | Идентификаторы для копирования | id роли, код комнаты |
| Блок кода | Сырой текст, который нельзя интерпретировать | лог, транскрипт |
| `[текст](url)` | Ссылка-маска. **Работает** в `TextDisplay` | `[перейти к сообщению](…)` |
| `<t:1712345678:R>` | Время в поясе читателя | `закроется <t:…:R>` |

Даты — **только** через `discord.utils.format_dt`. Доступные стили: `f F d D t T R`. Ручных «14.03 в 18:40 МСК» не бывает: у половины сервера другой пояс.

Числа: `**1 284**` сообщений — жирным только само число.

## 4. Семь архетипов карточки

Любое сообщение бота — один из семи. Новый архетип заводится осознанно, с правкой этого файла.

**Исключение YouTube (15e):** новое видео — обычное сообщение (`content` в очередь логов), не карточка V2 и не `discord.Embed`. Шаблон: `{role} Новое видео на канале **{channel}**: **{title}**` и ссылка. Движения нет.

### A. Ответ на команду (`panel`)

```
┌ INFO ──────────────────────────────
│ ## ▸ Режим бота
│ Сбор данных: роли, каналы и права бот не меняет.
│
│ **Мутации:** заперты
│ **Выдача ролей:** выключена
│ -# снимается только в .env и перезапуском
└────────────────────────────────────
```

### B. Панель с управлением (`panel` + `rows`)

Кнопки — дети `Container`, под `Separator`. Порядок в ряду: **частое → редкое → опасное**. Опасное (`ButtonStyle.danger`) всегда последнее в последнем ряду.

```
┌ INFO ──────────────────────────────
│ ## ▸ Комната Ann
│ **Владелец:** @Ann
│ **Лимит:** 5 · **Замок:** открыт
│ -# кнопки видит только владелец и старший+
│ ─────────────────────────────────
│ [Переименовать][Лимит][Запереть][Впустить]
│ [Передать ▾][Выгнать ▾]              [Удалить]
└────────────────────────────────────
```

### C. Подтверждение (`confirm`)

Появляется **на месте** исходной карточки через `interaction.response.edit_message`, не новым сообщением. Две кнопки: `danger` с точным глаголом и `secondary` «Отмена». Таймаут 60 секунд, после чего карточка сама переходит в «истекло».

```
┌ DANGER ────────────────────────────
│ ## ⚠ Закрыть тикет #124?
│ Канал будет удалён, транскрипт уйдёт в архив.
│ -# отменится само <t:…:R>
│ ─────────────────────────────────
│ [Да, закрыть]                 [Отмена]
└────────────────────────────────────
```

### D. Результат действия (`receipt`)

Итог необратимой операции. Кнопок нет — или ровно одна («Отменить», пока действует окно отката).

```
┌ DANGER ────────────────────────────
│ ## ⚑ Дело #128 — тайм-аут
│ **Кому:** @user
│ **Срок:** 2 ч, до <t:…:t>
│ **Причина:** оскорбления в голосовом
│ -# следящий @Ann · репутация 78 → 76
└────────────────────────────────────
```

### E. Список (`listing`)

Максимум 10 строк на страницу, счётчик `1/4`, кнопки `←` `→`. Строки одинаковой формы. Если строк ноль — архетип G.

```
┌ INFO ──────────────────────────────
│ ## ▸ Следящие · 12
│ ### Главные
│ **@Ann** · ◷ на смене · 4 дела за неделю
│ **@Bob** · нет
│ ### Старшие
│ …
│ -# страница 1/2
│ ─────────────────────────────────
│ [←][→]                    [Обновить]
└────────────────────────────────────
```

### F. Событие в лог-канал (`event`)

Всегда одинаковая форма: **что** → **кто** → **где** → **детали** → `-#` метка источника. Без кнопок. Компактно: лог читают пачками.

```
┌ DANGER ────────────────────────────
│ ## ✕ Сообщение удалено
│ **Автор:** @user
│ **Канал:** #общий
│ > текст сообщения
│ -# логи участников · <t:…:T>
└────────────────────────────────────
```

### G. Пустое, отказ, ошибка

```
┌ MUTED ─────────────────────────────      пусто
│ ## Ничего не нашлось
│ За выбранный период дел нет.
│ -# попробуйте период 30 дней
└────────────────────────────────────

┌ MUTED ─────────────────────────────      нет прав
│ ## 🔒 Не хватает прав
│ Это делают старшие следящие и выше.
│ -# ваш ранг: следящий
└────────────────────────────────────

┌ DANGER ────────────────────────────      сбой
│ ## ✕ Не получилось
│ Discord не ответил вовремя. Повторите через минуту.
│ -# код E-4173 · записан в лог бота
└────────────────────────────────────
```

Ошибка **всегда** несёт короткий код: `E-` плюс 4 шестнадцатеричных знака от идентификатора взаимодействия. Пользователь называет код — следящий находит ту же метку в `#лог-администрации` (команда, канал, кто, права Discord и ранг, нехватка прав бота, файл:строка) и в `structlog`. Трассировка наружу не уходит никогда.

## 5. Движение и живые состояния

Контракт этого раздела реализует `presentation/motion.py`.

### Что в Discord вообще возможно

Настоящей анимации внутри сообщения нет. Ощущение движения даёт ровно пять приёмов, и их надо различать по цене.

| Приём | Цена | Где применять |
| --- | --- | --- |
| **Живая метка времени** `<t:…:R>` | **ноль запросов** — обновляется клиентом каждую секунду | Обратный отсчёт, «закроется через», «истечёт», «удалится через». Приём номер один: даёт живое сообщение бесплатно |
| **Анимированный значок приложения** | ноль запросов после загрузки | Крутящийся индикатор в заголовке работающей карточки, пульсирующая точка «идёт запись» |
| **Каскад правок** | 1 запрос на кадр | Прогресс длинной операции: приём истории, чистка сообщений, массовая выдача ролей |
| **Скелет и заполнение** | 1–2 запроса | Тяжёлый ответ: сначала рамка с «собираю», затем готовая карточка на том же месте |
| **Собственное состояние Discord** | ноль запросов | `defer(thinking=True)` — стандартная анимация «бот думает» на время до 15 минут |

Шестого приёма нет. Всё, что выглядит как анимация помимо этого, — это правки, и они стоят запросов.

Сообщение YouTube в `#видео` не использует ни один из пяти приёмов: это `content`, без правки после публикации (кроме обычной очереди отправки).

### Анимированные значки приложения

Ключевой приём 2026 года: **эмодзи приложения** не занимают слоты сервера и работают в любой гильдии, где есть бот. Раньше для крутящегося индикатора приходилось держать «эмодзи-сервер»; теперь нет.

```python
# один раз при развёртывании
emoji = await bot.create_application_emoji(name="load", image=gif_bytes)

# в коде — рендер по id, без обращения к API
str(discord.PartialEmoji(name="load", id=emoji.id, animated=True))   # -> <a:load:...>
```

Реестр значков (`presentation/motion.py`), с обязательным текстовым запасным вариантом на случай, если эмодзи не загружены:

| Имя | Вид | Запасной | Где |
| --- | --- | --- | --- |
| `load` | кольцевой индикатор, анимированный | `⏳` | Заголовок работающей карточки |
| `dots` | три пульсирующие точки | `…` | «Идёт запись», «ждём ответа» |
| `tick` | галочка с проявлением | `✓` | Завершённый шаг |
| `cross` | крест с проявлением | `✕` | Провалившийся шаг |
| `bar_l` `bar_f` `bar_e` `bar_r` | сегменты полосы: левый край, заполнено, пусто, правый край | `▰` `▱` | Полоса прогресса «как у больших ботов» |

Правило: **бот обязан работать без единого загруженного значка**. Реестр — украшение поверх текстового слоя, а не зависимость. `/diagnose` показывает, загружены значки или используется запасной набор.

### Полоса прогресса

Два исполнения одного контракта:

```
meter(7, 10)                 ▰▰▰▰▰▰▰▱▱▱  70%        текстовое, работает всегда
bar(7, 10)                   ▰▰▰▰▰▰▰▱▱▱  70%        то же на сегментных значках, если они есть
```

Ширина 10 знаков, число рядом обязательно: полоса без числа не читается на телефоне.

### Бюджет правок

Нарушение бюджета даёт мигание у читателя и `429` у Discord. Это не рекомендация, это часть приёмки.

| Ситуация | Не чаще |
| --- | --- |
| Правка одного сообщения | **1 раз в 2 секунды** |
| Правка ответа на взаимодействие | 1 раз в 2 секунды, и не больше 30 правок на операцию |
| Первый кадр после старта | сразу, без задержки: человек должен увидеть отклик мгновенно |
| Последний кадр | всегда доставляется, даже если бюджет исчерпан |

Контроллер сам решает, что показать: он не «спит между кадрами», а **пропускает** кадры, которые не влезли в бюджет. Прогресс, который отстаёт от работы, лучше, чем работа, которая ждёт прогресс.

Дополнительно: если операция короче 2 секунд, кадр «идёт» **не показывается вовсе**. Мелькнувшая и исчезнувшая карточка выглядит как сбой.

### Контракт `presentation/motion.py`

```python
class Progress:
    """Живая карточка длинной операции. Сама следит за бюджетом правок."""

    def __init__(self, target: Sendable, *, title: str, total: int | None = None,
                 min_interval: float = 2.0, show_after: float = 2.0) -> None: ...

    async def start(self) -> None: ...                      # первый кадр, если работа затянулась
    async def step(self, done: int, note: str | None = None) -> None: ...   # кадр, может быть пропущен
    async def stage(self, name: str, state: StageState) -> None: ...        # чек-лист этапов
    async def finish(self, view: ui.LayoutView) -> None: ...                # финал, доставляется всегда
    async def fail(self, code: str) -> None: ...                            # провал, тон DANGER

class Countdown:
    """Обратный отсчёт без единой правки: живёт на <t:…:R>."""
    def render(self, until: datetime) -> str: ...

async def reveal(target, frames: Sequence[ui.LayoutView], *, interval: float = 2.0) -> None:
    """Постановочный каскад: несколько кадров подряд. Только для сцен из §5.7."""
```

`Progress` используется как контекстный менеджер: выход по исключению сам вызывает `fail()` с кодом ошибки, так что незавершённая карточка «идёт» не остаётся висеть навсегда. Это отдельное требование приёмки: **застрявшая карточка прогресса — дефект**.

### Сцены

Именованные сценарии. Реализация обязана совпадать по составу кадров.

**Сцена 1. Длинная операция с известным объёмом** (приём истории, чистка сообщений, массовая выдача ролей)

```
кадр 0, сразу     ┌ RUNNING ───────────────────────
                  │ ## <a:load:…> Читаю историю
                  │ Собираю сообщения, ответы и реакции.
                  │ -# это может занять несколько минут

кадр N, раз в 2 с ┌ RUNNING ───────────────────────
                  │ ## <a:load:…> Читаю историю
                  │ ▰▰▰▰▰▰▱▱▱▱ 24 из 40 каналов
                  │ **Сообщений:** 18 402
                  │ -# сейчас: #флудилка

финал             ┌ OK ────────────────────────────
                  │ ## ✓ История собрана
                  │ **18 402** сообщения · **40** каналов
                  │ авторов **312** · связей **1 044**
                  │ -# дальше: /stats person, /stats ties
```

Правило: **финальная карточка заменяет карточку прогресса на том же месте**. Второе сообщение не отправляется.

**Сцена 2. Удаление сообщений с прогрессом** (`/purge`)

Пачками по 100, между пачками кадр. Именно здесь живая карточка нужна больше всего: человек должен видеть, что чистка идёт, и сколько осталось.

```
кадр    ┌ RUNNING ───────────────────────
        │ ## <a:load:…> Чищу канал
        │ ▰▰▰▰▰▰▰▱▱▱ 700 из 1000
        │ **Пачка:** 7 из 10
        │ -# сообщения старше 14 суток пропускаются

финал   ┌ OK ────────────────────────────
        │ ## ✓ Канал очищен
        │ **Удалено:** 934 · **пропущено по возрасту:** 66
        │ **Канал:** #общий · **инициатор:** @Ann
        │ -# дело #131 · <t:…:T>
```

Карточка прогресса — **ephemeral для инициатора**. Итог — в канал логов. Иначе чистка канала оставляет в нём же мусор.

**Сцена 3. Обратный отсчёт** (розыгрыш, сбор, автозакрытие тикета)

Ни одной правки до самого конца. Всё живое время рисует `<t:…:R>`.

```
                  │ **Итог:** <t:1712345678:R>       ← клиент сам тикает
```

Правки только на: изменение счётчика участников (с задержкой, пачками, не чаще раза в 5 секунд) и на финал.

**Сцена 4. Чек-лист этапов** (создание комнаты, открытие тикета, запуск сбора)

Операция из 3–5 шагов, каждый мгновенный, но вместе заметные. Кадр на каждый шаг.

```
        ┌ RUNNING ───────────────────────
        │ ## <a:load:…> Открываю тикет
        │ ✓ Проверил лимит
        │ ✓ Создал канал
        │ <a:dots:…> Выдаю доступ
        │ ▫ Пишу карточку
```

Пройденные шаги — `✓`, текущий — анимированный, будущие — `▫`. Проваленный — `✕`, и карточка немедленно уходит в `fail()`.

**Сцена 5. Скелет и заполнение** (тяжёлая сводка: `/stats overview`, `/watchers list`)

```
кадр 0  ┌ RUNNING ───────────────────────
        │ ## <a:load:…> Собираю сводку
        │ -# считаю по 600 участникам

финал   ┌ INFO ──────────────────────────
        │ ## ▸ Сводка сервера
        │ …
```

Применяется, только если сборка дольше 2 секунд. Иначе сразу финал.

**Сцена 6. Печать бота** (`channel.typing()`)

Для коротких ответов в канал, когда карточка ещё не готова, а сообщение не ephemeral. Стандартный индикатор Discord, ноль правок.

**Сцена 7. Постановочный каскад** (`reveal`)

Единственное место, где движение допускается ради впечатления, а не ради информации: **объявление победителя розыгрыша**.

```
кадр 1   ## 🎉 Розыгрыш окончен
         <a:load:…> Выбираю…

кадр 2   ## 🎉 Розыгрыш окончен
         **Участников:** 84 · **Победителей:** 2
         <a:dots:…> Барабанная дробь

кадр 3   ## ★ Nitro на месяц
         **Победители:** @Ann · @Bob
         -# провёл @Cid · перевыбор доступен 24 часа
```

Три кадра, интервал 2 секунды, итого 4 секунды. Больше трёх кадров — уже не эффект, а задержка. Каскад применяется **только здесь**; для всего остального он в списке анти-паттернов.

### Где движение запрещено

- В **лог-каналах**. Логи читают пачками и листают; мигающие карточки делают канал нечитаемым.
- В **отказах и ошибках**. Провал показывается сразу и статично. Анимация ожидания перед словом «отказано» выглядит издевательством.
- В **постоянных панелях**. Панель хаба, панель тикетов, панель сбора живут неделями. Их правят только при изменении данных.
- В операциях **короче 2 секунд**.
- В **ephemeral-ответах**, которые человек всё равно закроет через секунду.

## 6. Состояния во времени

| Состояние | Как выглядит |
| --- | --- |
| Идёт | Тон `RUNNING`, анимированный значок в заголовке, кнопки `disabled` |
| Долго | Кадры по бюджету из §5, пропуск вместо ожидания |
| Готово | Карточка **редактируется на месте**, вторая не шлётся |
| Истекло | Кнопки `disabled`, тон `MUTED`, `-# срок истёк, вызовите команду заново` |
| Завершено | `disabled_copy(view)` — кнопки серые, карточка остаётся историей |
| Провалено | Тон `DANGER`, код `E-xxxx`, движение остановлено немедленно |

Правило трёх секунд: любой обработчик, который не отвечает мгновенно, сначала делает `defer`, потом работает. Иначе Discord покажет «Что-то пошло не так». `defer(thinking=True)` даёт собственную анимацию Discord и окно до 15 минут.

## 7. Тон текста

| Нельзя | Нужно |
| --- | --- |
| «Ошибка выполнения операции» | «Не получилось выдать роль: она выше роли бота» |
| «Пользователь не найден» | «Этого человека нет на сервере» |
| «OK» на кнопке | «Закрыть тикет» |
| «Вы не имеете достаточных прав» | «Это делают старшие следящие и выше» |
| «Invalid input» | «Имя длиннее 32 символов» |
| «Роль успешно выдана!» | «Роль выдана» |
| «Подождите, идёт обработка…» | «Читаю историю: 24 из 40 каналов» |

- Обращение на «вы», без имени в каждой фразе.
- Без восклицательных знаков, кроме поздравления победителя розыгрыша.
- Отказ объясняет **причину и путь**: кто может это сделать или что изменить.
- Числа и сроки конкретные. Не «скоро», а `<t:…:R>`.
- Ошибка не обвиняет пользователя: «имя не подошло», а не «вы ввели неверное имя».
- Прогресс называет, что происходит **сейчас**, а не «пожалуйста, подождите».

## 8. Кнопки, `custom_id`, безопасность

### Схема id

```
c:{kind}:{action}:{ref}
```

`kind` — 2–4 буквы домена. `ref` — **первичный ключ строки в БД** или слаг `[a-z0-9_]{1,32}` (ключ каркаса), не snowflake пользователя. Пример: `c:tk:close:8412`, `c:sk:fix:cat_evidence`.

| kind | Домен |
| --- | --- |
| `vc` | комната |
| `tk` | тикет |
| `gw` | розыгрыш |
| `ev` | сбор |
| `gr` | группа |
| `pl` | опрос |
| `rep` | репутация (зарезервирован) |
| `md` | дело, досье, доказательства, обжалование в ЛС |
| `am` | автомод |
| `vf` | верификация |
| `sr` | роли по выбору |
| `st` | канал статистики (кнопок нет) |
| `lf` | поиск команды |
| `wh` | карточка следящего |
| `sk` | каркас и структура |
| `shw` | витрины панелей |
| `bp` | файл настройки |

YouTube кнопок не имеет. Старые `sh` (витрина) и `su` (поддержка) не используются. Новый вид витрины — `shw`, не `st` (статистика) и не `sh`.

Никогда `c:tk:close:{user_id}`. Владение проверяется в БД по `ref`, а не тем, что id совпал с нажавшим.

`kind` совпадает с доменом ключа прав и области мутаций: `tickets` / `channels.tickets` / `tk`.

### `DynamicItem` вместо ручного разбора

`custom_id` с переменной частью нельзя зарегистрировать как обычную постоянную панель. В discord.py 2.7 для этого есть `ui.DynamicItem`: шаблон-регулярка, один класс на все кнопки такого вида, восстановление после рестарта без хранения самого view.

```python
class TicketClose(ui.DynamicItem[ui.Button], template=r"c:tk:close:(?P<ticket>\d+)"):
    def __init__(self, ticket_id: int) -> None:
        self.ticket_id = ticket_id
        super().__init__(
            ui.Button(
                label="Закрыть тикет",
                style=discord.ButtonStyle.danger,
                custom_id=f"c:tk:close:{ticket_id}",
            )
        )

    @classmethod
    async def from_custom_id(cls, interaction, item, match, /):
        return cls(int(match["ticket"]))

    async def callback(self, interaction: discord.Interaction) -> None:
        ...

# один раз в setup_hook
bot.add_dynamic_items(TicketClose, TicketClaim, VoiceLock)
```

Статические кнопки без переменной части — обычная постоянная панель плюс `bot.add_view(view, message_id=…)`.

### Проверка в обработчике — обязательный порядок

1. `interaction.guild` не `None`: панель могли утащить в личные сообщения.
2. Ресурс по `ref` существует и не закрыт, иначе `MUTED` «карточка устарела».
3. Право: владелец ресурса **или** ключ действия **или** ранг не ниже порога.
4. Смена ролей — только брокер (`role_broker_allowed`). Каналы и баны открыты.
5. Иерархия, если действие направлено на человека.

Провал любого шага даёт ephemeral-карточку архетипа G. Провал шага 3 при подделанном `ref` — ещё и запись в лог следящих.

Порядок 3 → 4 не меняется: человек без прав не должен узнавать отказ брокера.

Ни один шаг не заменяется рассуждением «Discord же скрыл кнопку». Кнопку можно нажать по сохранённому взаимодействию.

## 9. `presentation/layout.py` — контракт

```python
def panel(
    title: str,                     # без значка, значок кладёт tone
    body: str | Sequence[str] = (),
    *,
    tone: Tone = Tone.INFO,         # определяет и цвет, и значок
    fields: Mapping[str, object] | None = None,
    footnote: str | None = None,    # уедет в -#
    rows: Sequence[ui.ActionRow] = (),
    thumbnail_url: str | None = None,
    files: Sequence[ui.File] = (),
) -> ui.LayoutView: ...

def kv(pairs: Mapping[str, object]) -> str: ...
def meter(done: int, total: int, width: int = 10) -> str: ...
def listing(rows: Sequence[str], page: int, pages: int) -> str: ...
def confirm(question: str, *, verb: str, custom_id: str, tone=Tone.DANGER) -> ui.LayoutView: ...
def denied(reason: str, *, need: str | None = None) -> ui.LayoutView: ...
def failure(error_code: str) -> ui.LayoutView: ...
def empty(what: str, *, hint: str | None = None) -> ui.LayoutView: ...
def disabled_copy(view: ui.LayoutView) -> ui.LayoutView: ...
def paginate(text: str, limit: int = 3800) -> list[str]: ...
def error_code(interaction: discord.Interaction) -> str: ...   # "E-" + 4 hex от id
```

Инварианты обеспечивает сам набор, а не вызывающий код:

- `AllowedMentions.none()` по умолчанию; пинг — явный аргумент `mentions=`.
- Сумма текста режется до 4000 с многоточием; при переполнении `paginate` возвращает страницы.
- Компонентов не больше 40: лишние ряды не теряются молча, а роняют тест разработчика.
- Значок и цвет берутся из `tone`, вручную не задаются.
- `content` вместе с layout передать невозможно: сигнатура этого не допускает.

Тест-контракт: снапшоты собирают view и проверяют лимиты, отсутствие сырых `0x`, английских служебных слов и `None` в тексте. Discord для этого не нужен.

## 10. Как выглядят конкретные фичи

Черновики финальных карточек. Реализация обязана совпадать по составу полей и порядку.

### Панель хаба войса (постоянная)

```
┌ INFO ──────────────────────────────
│ ## ▸ Свои комнаты
│ Зайдите в **➕ Создать комнату** — бот сделает
│ голосовой канал и отдаст его вам.
│
│ **Сейчас открыто:** 7 комнат · 23 человека
│ -# комната удалится через 40 с после того, как все выйдут
│ ─────────────────────────────────
│ [Моя комната][Как это работает]
└────────────────────────────────────
```

### Панель владельца комнаты

```
┌ INFO ──────────────────────────────
│ ## ▸ Комната «катка ранкед»
│ **Владелец:** @Ann · **В комнате:** 4/5
│ **Замок:** 🔒 закрыт
│ -# кнопки видит владелец и старший+
│ ─────────────────────────────────
│ [Имя][Лимит][Открыть][Впустить ▾]
│ [Передать ▾][Выгнать ▾][Заявки 2]
│ [Пригласить][Хочу войти]
└────────────────────────────────────
```

### `/owner seed`

Любой обслуживаемый сервер. Каталог по категориям: зачем строка, кто видит, цвет и hoist. Если на сервере уже есть неподключённые строки и у бота есть права — команда сразу подключает их, затем показывает обновлённый каталог. Пагинация: как собрать / лимиты Discord, затем категории каналов, затем группы ролей.

```
┌ WARN ──────────────────────────────
│ ## ⚠ Каркас сервера
│ Нет 12 · найдено 4 · привязано 20 · права 2.
│
│ Как собрать
│ 1. Создайте категории…
│ ─────────────────────────────────
│ [←] [→]
└────────────────────────────────────
```

Прогресс — сцена 4. Стадии: права бота, находки, права каналов, привязка, панели, данные, перепись. Ошибка стадии — `✕` (`FAIL`), не галочка.

```
┌ RUNNING ───────────────────────────
│ ## <a:load:…> Каркас сервера
│ ✓ права бота
│ ✓ роли
│ <a:dots:…> категории
│ ▫ каналы
│ ▫ привязка
```

Итог — архетип D. Без латинского Special: ранг пишется «ранг специальный» или именем роли.

```
┌ OK ────────────────────────────────
│ ## ✓ Каркас сервера
│ Роли: новых 15, уже были 0.
│ Каналы: новых 19, уже были 0.
│ Привязано: логи, ранги, хаб, …
│ Ранг специальный владельцу: да.
```

Отказ до подтверждения (нет прав или роль бота ниже каркаса) — архетип `denied`, не отчёт после кнопки.

│ ## ▸ Репутация

## 11. Анти-паттерны

- Пустой `Container` только ради рамки под кнопками.
- Второе сообщение вместо правки при завершении долгой операции.
- Кнопка, которая молча ничего не делает при нехватке прав.
- `ephemeral=False` для служебных ответов: засоряет канал.
- Собственные форматы дат и «через 5 минут» вместо `<t:…:R>`.
- Дублирование одного и того же в заголовке и в теле.
- Три ряда кнопок там, где хватает одного селекта.
- `@everyone` и `@here` в любом автоматическом сообщении.
- Значки в `-#` подписи.
- Легаси-эмбед в новом коде.
- **Правка чаще бюджета** из §5: мигание у читателя и `429` у Discord.
- **Карточка «идёт», которая осталась висеть** после сбоя: `Progress` обязан завершаться и в исключении.
- **Каскад ради красоты** где угодно, кроме объявления победителя розыгрыша.
- **Прогресс на операции короче 2 секунд**: мелькнувшая карточка читается как сбой.
- **Ссылка на discordserver.info / myserver.gg / Disboard в правилах** после вывода каталожных ботов: человек уходит туда, где сервера уже нет.
- **Капча или три синонима `/like` `/up` `/bump`:** этих команд нет; вместо `/info` — `/stats` → Сейчас.
- **Эмбед или карточка V2 для нового видео YouTube:** только `content` в очередь.

## 12. Легаси

Эмбедов в коде не осталось: логи участников и аудита — такие же карточки V2, а появление `discord.Embed` в исходниках роняет тест. Из-за необратимости флага `IS_COMPONENTS_V2` уже отправленные когда-то эмбеды в каналах так и остаются эмбедами — переписывать их нечем и не нужно.
