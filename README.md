# Conductor

Discord-бот для одного сообщества на **Python 3.12+** и **discord.py 2.7**: каркас сервера, верификация, роли по выбору, поиск команды, голосовые комнаты, тикеты, модерация с досье и квотами, репутация и лестница, достижения, статистика и пульс.

Основной и тестовый Conductor — **два разных приложения Discord**, у каждого свой токен. Процесс живёт только на серверах из своего `GUILD_IDS`; с любого другого выходит сам. Оба бота изначально приватные (`Public Bot` выкл). Владелец приложения Discord и id из `OWNER_USER_IDS` обходят ранги и ключи. Галка Discord «Администратор» открывает команды бота **только пока ранг Специального никому не привязан** — это временный вход свежего сервера; после привязки она даёт лишь обход лимитов. Если роль Специального исчезнет, запасной вход откроется снова.

Интерфейс — русский, Components V2. Всё, что настраивается, живёт в `/admin panel`; отдельных `/setup` и `/config` нет.

## Запуск

Нужны Docker и заполненный `.env`. Локальный Python без Docker работает на SQLite и годится для разработки, не для сервера.

1. Создайте **два** приложения в [Discord Developer Portal](https://discord.com/developers/applications): основное и тестовое. У обоих выключите **Public Bot**, включите Privileged Gateway Intents: **Server Members** и **Message Content**. Интент личных сообщений бот включает сам — в портале галка не нужна, **Presence** не обязателен.
2. Пригласите каждого бота только на его серверы, с правами из `domain/permissions.py: REQUIRED_PERMISSIONS`: Manage Roles, Manage Channels, Ban Members, Kick Members, Moderate Members, Move Members, Manage Messages, View Audit Log, Create Instant Invite. Роль бота — **выше** ролей каркаса.
3. `Copy-Item .env.example .env` и заполните оба токена, списки серверов, `BOT_MODE` (какой из двух запустить) и `POSTGRES_PASSWORD`.
4. Поднимите стек. Один `.env` запускает только выбранный режим. Оба вместе — второй файл `.env.test` и `docker compose --profile test`. Пошагово до `/admin` → Каркас — [docs/SETUP.md](docs/SETUP.md). Приёмка — [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

Windows (Docker Desktop с зелёным статусом) — двойной щелчок по `start.bat` или:

```powershell
.\start.ps1
```

Скрипт гасит старые копии, собирает образы, поднимает **postgres + bot** и показывает логи. `Ctrl+C` закрывает только просмотр логов. Без логов — `.\docker-up.ps1`. Полная остановка — `.\stop.ps1`.

Пустой Ubuntu 24.04 — от SSH до автозагрузки и бэкапов: [deploy/ubuntu-24.04/README.md](deploy/ubuntu-24.04/README.md).

```bash
sudo bash deploy/ubuntu-24.04/bootstrap.sh --ufw
./deploy/ubuntu-24.04/check-env.sh
./deploy/ubuntu-24.04/start.sh
```

## Первые шаги на сервере

1. `/diagnose` → **Настройка**: интенты, права, позиция роли — без красного.
2. `/admin` → **Каркас** → **Собрать сервер**. Бот создаёт недостающее сам. Свои каналы — сначала **Сопоставить существующие**.
3. `/admin` → **Каркас** → **Витрины** → **Отправить все недостающие**.
4. Правила в `#правила` пишет владелец сервера: бот в этот канал не пишет.
5. `/diagnose` → **Готовность**: должно быть «сервер готов к работе».

Подробно, включая вывод каталожных ботов и порядок для живого сервера со старой репутацией: [docs/SETUP.md](docs/SETUP.md).

## Переменные окружения

Каноническая матрица в том же порядке, что `.env.example`. Пустая строка = «не задано». Без токена выбранного `BOT_MODE` запуск останавливается.

| Переменная | Умолчание | Зачем |
| --- | --- | --- |
| `BOT_MODE` | `live` | какой бот запускает этот процесс: `live` или `test`/`beta` |
| `DISCORD_TOKEN` | — | токен основного приложения; используется при `BOT_MODE=live` |
| `GUILD_IDS` | — | серверы основного бота; с любых других он выйдет |
| `PUBLIC_GUILD_ID` | — | запасной id, если `GUILD_IDS` пуст и `BOT_MODE=live` |
| `TEST_DISCORD_TOKEN` | — | токен тестового приложения; используется при `BOT_MODE=test`/`beta` |
| `TEST_GUILD_IDS` | — | серверы тестового бота при `BOT_MODE=test`/`beta` |
| `TEST_GUILD_ID` | — | запасной id, если `TEST_GUILD_IDS` пуст и режим test/beta |
| `OWNER_USER_IDS` | пусто | дополнительные разработчики кроме владельца приложения Discord |
| `LOG_LEVEL` | `INFO` | уровень лога процесса |
| `DATA_DIR` | `<корень проекта>/data`, в образе `/app/data` | SQLite, `.command-hash`, `automod.yml`, `.heartbeat` |
| `DATABASE_URL` | SQLite в `DATA_DIR` | в Docker собирается из `POSTGRES_*` |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` / `POSTGRES_PORT` | `conductor` / — / `conductor` / `5432` | Docker |
| `TZ` | `Europe/Moscow` | часовой пояс контейнеров |
| `MESSAGE_CACHE_SIZE` | `20000` | сообщений в памяти |
| `MESSAGE_CACHE_TTL` | `3600` | срок текста в кэше, секунды |
| `DATA_RETENTION_DAYS` | `90` | производные агрегаты; `0` — не чистить их |
| `TICKET_TRANSCRIPT_DAYS` | `365` | транскрипты тикетов; `0` — не чистить |
| `SQLITE_BACKUP_KEEP` | `7` | снимки SQLite; `0` — не снимать |
| `VOICE_ROOMS_PER_MEMBER` | `1` | личных комнат на участника (1–20) |
| `TICKETS_PER_CATEGORY` | `1` | открытых обращений одной категории на участника (1–20) |
| `INTERACTION_LIMIT_PER_MINUTE` | `50` | потолок нажатий на гильдию в минуту; `50` = взять из `RATE_PROFILE` (edge: 1200). Окно на человека задаёт профиль |
| `RATE_PROFILE` | `edge` | темп REST: `edge`, `balanced`, `safe`. `safe` — аварийный откат |
| `GLOBAL_RPS_TARGET` | пусто | переопределить глобальный темп профиля (1–50). Пусто = из профиля |
| `OUTBOUND_CONCURRENCY` | пусто | сколько REST сразу. Пусто = из профиля |
| `MAX_RATELIMIT_WAIT` | пусто | сколько discord.py ждёт 429 внутри вызова, секунды |
| `INVALID_REQUEST_STOP` | пусто | при стольких недопустимых за 10 мин остановить USER/STAFF/BACKGROUND |
| `FORCE_SYNC` | `false` | принудительная публикация слэш-команд |
| `AUTO_MIGRATE` | пусто: SQLite да, Postgres нет | в Docker задан `true`; иначе нужен `conductor db upgrade` |

Слэш-команды публикуются только на серверы забора и только если дерево команд изменилось; хеш — в `<DATA_DIR>/.command-hash`. Принудительно — `FORCE_SYNC=true`.

## Каталог данных

Один каталог на всё состояние вне базы. В Docker это `./data` на хосте, примонтированный в `/app/data`.

| Файл | Что это |
| --- | --- |
| `automod.yml` | правила автомодерации, источник правды (см. ниже) |
| `automod.yml.example` · `permissions.yml.example` | эталоны; первый запуск в Docker кладёт `automod.yml` из эталона |
| `.command-hash` | слепок дерева команд, чтобы не синхронизировать его каждый старт |
| `.heartbeat` | отметка живости, её читает healthcheck контейнера |
| `conductor.db`, `backups/` | только SQLite-режим; в Docker база живёт в Postgres |

Стереть всё состояние бота (база, снимки, `data-test`, дампы `backups/`, рабочие файлы) и начать настройку заново: `python scripts/wipe_data.py --yes`. Эталоны `*.yml.example` и `.env` остаются. Каркас Discord скрипт не удаляет.

## Автомодерация: файл правил

Правила живут в `<DATA_DIR>/automod.yml`. Это источник правды: лимиты, действия и исключения из `/admin` не настраиваются — там только срабатывания и заявки.

1. Скопируйте `data/automod.yml.example` в `data/automod.yml` и поправьте лимиты. В Docker это делает первый запуск.
2. Бот читает файл при старте и по кнопке **«Перечитать файл»** на карточке в `#автомод`.
3. Опечатка в ключе — прежняя конфигурация остаётся, в лог администрации уходит «файл правил не принят: путь · ошибка».
4. Нет файла — работают встроенные умолчания, `/diagnose` ставит ⚠.

Окно счёта живёт в памяти: рестарт обнуляет текущий час, строки `automod_hits` остаются. Правило без ключа в `rules` выключено. Изменить правила без доступа к файлу можно только заявкой владельцу бота — кнопка там же.

## База и миграции

Схема — Alembic в `src/conductor/db/migrations` (текущий head — `0067`). Имена индексов и ограничений задаёт `naming_convention` в `db/models.py`.

На SQLite миграции применяются при старте. На Postgres `AUTO_MIGRATE` по умолчанию выключен: **обязательный шаг деплоя** — `conductor db upgrade` либо `AUTO_MIGRATE=true` (Compose подставляет его сам). Если миграции при старте выключены, бот сверяет ревизию с head и отказывается стартовать на устаревшей схеме.

```
conductor db upgrade      # применить
conductor db current      # текущая ревизия
```

Существующая `data/conductor.db` без таблицы версий не пересоздаётся: бот видит таблицу `members`, штампует ревизию `0001` и догоняет head. Данные остаются.

**Новая таблица.** Модель в `db/models.py` (гильдейская таблица несёт `guild_id`, snowflake — `BigInteger`, время — `DateTime(timezone=True)`) → `conductor db revision -m "voice_rooms"` → вычитать сгенерированный файл → `conductor db upgrade`. Колонку не удаляют в той же ревизии, в которой перестали её писать.

**Откат** — осознанный шаг, в `conductor db` его нет специально: `alembic downgrade -1` из корня репозитория, предварительно скопировав базу.

## Данные участников

На вопрос «что вы про меня знаете» отвечает бот, а не чтение базы: `/admin panel` → Данные, кнопки экспорта (`data.manage`) и «Забыть» (`data.forget`). Отдельных команд нет.

| Что | Сколько живёт | Как удалить |
| --- | --- | --- |
| Текст сообщения в памяти | 1 час (`MESSAGE_CACHE_TTL`) | истекает сам; «Забыть» сбрасывает сразу |
| Дневные счётчики, каналы, связи, ingest | 90 дней (`DATA_RETENTION_DAYS`) | ночная чистка; «Забыть» — для одного человека |
| Открытые голосовые сессии старше 48 ч | закрываются с пометкой `truncated` | ночная чистка |
| Закрытые голосовые сессии, события репутации без дела | те же 90 дней | ночная чистка; события с `case_id` остаются |
| Смены ролей | 180 дней | ночная чистка |
| Устаревшие панели | 7 дней | ночная чистка |
| Действия следящих | 365 дней | ночная чистка |
| Срабатывания автомода | 90 дней | ночная чистка |
| Транскрипты тикетов | 365 дней (`TICKET_TRANSCRIPT_DAYS`) | ночная чистка |
| Карточки бота в логе участников | 90 дней (`/admin` → Логи) | ночная чистка, только сообщения бота |
| Обезличенные счётчики сервера | те же 90 дней | остаются при «Забыть»: имён в них нет |
| Тикет, комната, розыгрыш, опрос, сбор, группа | пока жива операция | «Забыть» обнуляет `owner_id`, строку не удаляет |
| Снимок SQLite | 7 файлов (`SQLITE_BACKUP_KEEP`) | ротация в `data/backups/` |

`VACUUM INTO` пишет **полную копию** живой SQLite, поэтому restore из `data/backups/` вернёт и тех, кого уже забыли. Снимок **не для GDPR**: это откат сервера, не доказательство удаления. На Postgres такие файлы не пишутся — там `pg_dump`, см. [docs/DEPLOY.md](docs/DEPLOY.md).

## Разработка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests
```

1214 тестов, полный прогон около полутора минут: миграции применяются один раз за сессию, дальше схема реплеится из слепка (маркер `real_migrations` прогоняет всю цепочку по-настоящему). Правило зависимостей между слоями и запрет прямого `add_roles` проверяются тестом `tests/test_layering.py`, а не договорённостью — см. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

```
src/conductor
  bot.py            сборка: интенты, сессии, фон, забор серверов
  config.py         Settings из .env
  db/               модели, сессии, Alembic
  domain/           чистые правила: ранги, пороги, счёт, каркас
  services/         оркестрация: БД, Discord API, очереди, брокер ролей
  presentation/     Components V2, строки, движение
  cogs/             слэш-команды и слушатели шлюза
```

Публичная копия рабочего репозитория: история изменений осталась в приватной версии.
